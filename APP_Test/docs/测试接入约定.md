# 测试接入约定 v1

日期：2026-11-18。公共业务接口沿用 `依据/接口与数据约定.md` 的 v1.1，不新增另一套 Auth/Trip/Journal API。本文列的是为了测试先行而提出的内部接入约定，页面与部分业务尚未实现，不能描述为现有能力。

## 1. 目标工程与骨架

目标根目录包含 `package.json`、`apps/api`、`apps/web` 和 `packages/shared`。API 构建到 `apps/api/dist`，导出 `app.js#createApp(options)`；应用自身注册认证、行程、B 与 D 模块，不能在全软件测试中临时替换业务为假实现。

原规划测试仍需 B 的类/函数导出，完整列表在 `scripts/app-run.cjs` 的 `skeleton` 中。只是缺少未实现业务 HTTP 路由时不做“文件存在即通过”，会发实际请求验证状态、结构和持久化。缺构建、依赖或导出属于环境问题，应先修复骨架。

普通 HTTP 测试自动关闭模型和正式地图调用，使用两个真实注册用户。目录/迁移来自目标版本，测试不复制一套业务数据库实现。

## 2. 配置与内部数据库约定

| 名称                     | 用途                                            | 状态                                             |
| ------------------------ | ----------------------------------------------- | ------------------------------------------------ |
| `DATABASE_URL`           | 测试装配注入带独立 schema 的连接串              | 已有工程配置                                     |
| `MEDIA_STORAGE_DIR`      | 媒体存储的根目录；测试注入独立临时目录          | 本轮提出的内部配置接入点，D 需实现或共同更新映射 |
| `AUTH_TOKEN_TTL_SECONDS` | 令牌有效秒数；A13 使用 1 秒验证真正到期         | 本轮提出的内部测试配置，C 需实现或共同更新映射   |
| `JWT_SECRET`             | 测试进程的合成签名密钥，仅当实现采用 JWT 时使用 | 不规定令牌必须是 JWT；采用其他配置时集中调整装配 |

用户注册的最小密码长度、哈希算法和令牌编码未在 v1.1 定死，本测试不凭空新增这些产品规则。真实认证测试使用合成的较长密码并真实注册/登录。规划隔离测试只在必要时填入不可用于登录的合成凭据列，不把该身份作为真实认证证据。

C 文档约定的行程表使用 `trips`、`trip_selections`、`trip_days`、`trip_items`。完整迁移/故障注入测试暂约定 D 表名为 `visited_places`、`journals`、`media_assets`。D 的实际表名尚未在公开契约定稿，实施前应与 D 确认；若名字不同，集中调整数据库测试和 `world.failInsert` 的映射并记录变更，不降低 HTTP/事务行为要求。

SQL 故障只注入当前用例 schema；触发器在第一条或第二条插入时抛错，验证真实回滚，不在测试仓库中模拟一次失败就算数据库通过。U12 先成功上传并确认实际使用隔离目录，再注入元数据插入失败检查文件补偿。

## 3. 页面入口与定位标识

沿用 A 的建议路由：`/login`、`/register`、`/trips`、`/trips/new`、`/trips/:id/edit`、`/trips/:id/preview`、`/trips/:id`、`/footprints`、`/journals/:id`。

下面的 `data-testid` 是本轮测试先行定义的页面接入契约。它们用于稳定定位，不应在界面显示这些技术名称，也不强制组件文件名或 CSS 类。若前端已有等价可访问名称，可协商统一替换测试定位器并记录映射。

| 场景           | `data-testid`                                                                                                         | 要求                                                                          |
| -------------- | --------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 注册/登录      | `auth-email`、`auth-password`、`auth-display-name`、`auth-login-submit`、`auth-register-submit`                       | 可填写字段和提交按钮；登录后进入行程列表                                      |
| 行程列表       | `trip-list`、`trips-empty`、`new-trip`                                                                                | 空列表不伪装为请求失败                                                        |
| 新建草稿       | `trip-title`、`trip-city`、`create-trip`                                                                              | 城市控件使用 select 或提供等价测试映射                                        |
| 日期           | `trip-start-date`、`trip-end-date`、`save-dates`、`date-error`                                                        | date 输入，错误日期阻止生成                                                   |
| 偏好           | `theme-nature`、`pace`、`transport-mode`、`save-preferences`                                                          | 主题为 checkbox；节奏与交通为 select                                          |
| 景点           | `place-search`、`place-results`、`select-place-<UUID>`、`selected-places`、`selected-place-<UUID>`、`save-selections` | 景点选择 checkbox；保持选择顺序                                               |
| 城市变更       | `city-change-confirm`、`confirm-city-change`                                                                          | 显式确认旧选择被清空                                                          |
| 方案           | `generate-itinerary`、`proposal-preview`、`proposal-source`、`confirm-proposal`、`unassigned-places`                  | 未安排项存在时不可完整确认                                                    |
| 方案异常       | `warning-<CODE>`、`revision-conflict`、`proposal-expired`、`regenerate-itinerary`、`error-banner`                     | 根据 code 展示，保留输入和重新生成入口                                        |
| 正式日程       | `daily-schedule`                                                                                                      | 以服务端保存结果显示；刷新可重新登录后恢复                                    |
| 足迹导航与记录 | `nav-footprints`、`record-visit`、`visit-place`、`visited-on`、`save-visit`                                           | 先支持目录地点选择；只有实际到访才点亮                                        |
| 足迹展示       | `visit-marker-<UUID>`、`city-lit-<UUID>`、`map-unavailable`                                                           | 标记与城市同范围；地图失败状态可见                                            |
| 随笔入口       | `journal-list`、`new-journal-<visitedPlaceId>`、`edit-journal`                                                        | 地图失败不影响文字列表                                                        |
| 随笔编辑       | `journal-title`、`journal-body`、`journal-media-input`、`uploaded-media`、`save-journal`、`media-upload-error`        | 文件选择允许一次选多张，逐张调用单文件 API；每个已上传项一个 `uploaded-media` |
| 随笔详情       | `journal-body-text`、`journal-media-<mediaId>`                                                                        | 正文按文本；图片为带认证 fetch 后生成的 Blob URL                              |

业务页面尚未实现时，找不到这些控件属于页面业务失败，不写一个假页面来满足选择器。UI 测试中的可控 API 只隔离网络，页面本身仍必须来自目标工程。

## 4. 登录与浏览器约定

token 依原契约保存在内存，不要求用 localStorage 持久化。测试在刷新后重新执行登录，再进入原资源路径；服务端草稿/日程/手账仍须完整保存。

`browser.open` 在准备阶段通过浏览器 history/popstate 切换 SPA 路由，保持内存登录；真实 E2E 的新建、保存、确认、到访和图文提交均由可见控件完成。API 路由转发只作为本地代理，不篡改真实 E2E 的业务响应。

UI01— UI20 的固定响应只用于验证显示、请求形状和异常交互。EX 真实专项、SQL 事务和 E2E 不能用这些响应替代。

## 5. 暂未定稿的能力

后台文件清理任务的入口、重试状态与宽限期还需 D 给出契约；设备原始 WGS84 定位的公开转换接口尚未定义，不能直接更改标签冒充 GCJ-02。待确定后先增加相应失败测试，再实现。

真实地图 SDK 的城市边界来源、画布命中与视觉高亮还需真实浏览器 Key 及人工/专项验证。当前自动化断言覆盖页面标记/城市数据及加载失败，真实服务端高德由 EX03— EX05 验证，两者分别记录。
