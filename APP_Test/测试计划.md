## 1. 课程要求如何落地

按“先写测试 → Red → 最小业务实现 → Green → 重构”的顺序。每次实现或改进都对应既有失败用例；测试提交先于该轮业务实现提交，保留版本历史和运行日志。

本次仅编写测试及文档，不创建业务实现，不运行任何测试。

## 4. 测试环境与隔离

- Node.js 22.12+；测试工程自身依赖使用固定 lockfile 安装。
- 目标工程路径必须显式指定；构建 API 后测试，源码/构建/测试文件均保存哈希。
- 真库只使用服务器 Docker 的专用 `_test` 库；每项独立随机 schema，不清空共用数据库。
- 全软件 HTTP 测试真实注册登录；规划隔离测试的合成身份不替代认证验收。
- 图片使用合成 PNG/JPEG/WebP 与独立临时存储目录，不上传真实私人照片。
- 可控接口的 UI 测试与真实端到端分开标识；E2E 不使用假登录或假业务响应。
- 正式外部调用须显式开启，缺依赖算阻塞；模型必须保留真实 prompt、原始回复和校验结果。
