# D：足迹与地图手账开发说明

## 1. 你的交付

负责真实到访记录、城市点亮、随笔和图片接口，以及能交给 A 嵌入的地图组件。A 负责完整页面、随笔编辑表单、列表和详情布局；你提供组件和数据能力，不再做一套独立主应用。

当前这些模块都待开发。先读 [接口与数据约定](接口与数据约定.md)；重点区分“计划去”“实际去过”“写了一篇随笔”。只有实际到访参与城市点亮。

## 2. 文件放在哪里

HTTP 模块按 module/controller/service/dto 起步；查询多了再加 repository。地图组件不修改 App.tsx 的导航或 A 的全局样式，使用自己范围内的样式和可控容器尺寸。

## 3. 与 A 的组件接口

下面是目标属性；先据此做固定数据地图，再接真实服务。`markers` 与 `litCities` 使用共同 API 模型：

```ts
interface FootprintMapProps {
  markers: VisitedPlace[];
  litCities: {
    cityId: string;
    cityAdcode: string;
    cityName: string;
    visitCount: number;
  }[];
  selectedVisitedPlaceId: string | null;
  loading: boolean;
  errorMessage: string | null;
  onSelectVisitedPlace: (visitedPlaceId: string) => void;
  onPickLocation: (coordinates: Coordinates) => void;
}
```

类型定义从共享包以 type-only 导入。组件接收数据并返回用户操作，不自己决定登录、页面跳转或发出业务保存请求。A 收到回调后打开详情或到访表单，提交成功后重新获取地图数据。

D 负责地图 Key 未配置、资源加载失败、无数据、loading/error 状态和组件卸载清理。React 严格模式重复挂载不应重复堆积地图实例或监听器。浏览器地图依赖失败时，A 的手账文字列表仍能使用。

## 5. 实现顺序

1. 用固定 marks 和 litCities 做地图组件，输出地点选中、位置点选回调。提前把属性和截图交给 A。
2. 实现到访增删改查及按城市、年份聚合。删除最后一次到访后城市恢复未点亮，按年筛选时标记和城市聚合范围一致。
3. 实现纯文本随笔和到访归属检查。删除随笔保留到访；删除到访会删除相关随笔与媒体关联，界面需明确确认。
4. 实现单文件上传、授权读取，再实现随笔与图片关联。照片文件不塞进数据库 JSON 或共享代码包。
5. 完成城市边界加载、高亮、点选回看、图文联调、删除清理与故障恢复。

点亮至少使用有效城市 ID/行政区代码聚合；不能只改省份卡片颜色代替城市数据。行政边界来源和授权要在资源说明中记录，避免直接使用无来源图片当成可交互边界。

## 6. 图片与数据一致性

上传限制采用统一契约：实际 JPEG/PNG/WebP、10 MiB、一篇最多 9 张。检查文件内容与大小，生成存储名，不信任原始文件名及扩展名。文件不放在公开静态目录直接绕过授权读取。

存储用适配接口，例如 write/read/delete。开发可在后端专用目录保存，运行目录使用配置并加入忽略；正式运行有持久化卷。不得上传真实照片或写文件到 src。该路径变量需要你新增、接入配置服务并补 `.env.example`，目前尚无媒体配置。

写入与清理建议：

1. 文件写入成功再写媒体元数据；数据库写入失败，补偿删除新文件。
2. 保存随笔和媒体关联使用事务，验证所有者、最多 9 张、重复 ID、图片是否被其他随笔占用。
3. 删除随笔/到访先提交数据库变更，再删除不再被引用的文件。文件删除失败保留清理任务或可重试的临时状态，不回滚成一条指向已删除文件的随笔。
4. 无关联图片在宽限期后清理；宽限期和清理入口由你提供，不用随手清空整个目录替代。

私人图片读取需要身份验证。向 A 说明使用带 token 的 fetch 读取 Blob，而不是把 token 放到图片 URL。数据库只返回媒体 ID 和元数据，不泄露磁盘绝对路径。

## 7. 独立验证清单

| 场景                            | 预期                                  |
| ------------------------------- | ------------------------------------- |
| 有计划但没有到访                | 地图不点亮                            |
| 同城市两条到访，删除一条        | 城市仍点亮，visitCount 从 2 到 1      |
| 删除该城市最后一条到访          | 城市不再点亮，对应标记消失            |
| 删除一篇随笔                    | 到访和点亮保持                        |
| 无法确认城市                    | 保留标记，不虚构城市高亮              |
| 年份筛选                        | markers 与 litCities 基于相同到访集合 |
| 他人的到访/随笔/图片            | 不能关联、读取或删除，返回 404        |
| 伪装图片、超限文件、重复图片 ID | 拒绝且不留下已关联脏数据              |
| 文件写入后数据库失败            | 文件补偿清理                          |
| 数据库删除成功后文件删除失败    | 可重试清理，其他手账仍正常            |
| 地图缺 Key、加载失败、反复挂载  | 不崩溃、不泄漏实例，其他页面可用      |

后端测试使用 `apps/api/tests/*.test.cjs` 接入现有 npm test；纯业务单测无需地图 Key。地图浏览器测试需另启动 Vite 的开发宿主页，真实地图验证需配置浏览器 Key。当前尚无这些业务测试和宿主页，不能把固定 JSON 当成已经跑通。

从根目录可运行现有 `npm test`、`npm run dev:web`；真实数据库集成测试使用单独库，例如 `travel_planner_d_test`。完成后向 A 提供组件公共导出和最小使用示例，向全员提供接口正常/异常示例及自己的验证记录。
