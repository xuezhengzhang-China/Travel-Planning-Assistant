# 行程草稿后端与对接说明

## 已实现范围

所有路径前缀 /api，使用已有 Bearer token 鉴权。接口只从当前用户上下文取得 ownerId。

| 方法   | 路径                          | 输入/用途                                       |
| ------ | ----------------------------- | ----------------------------------------------- |
| POST   | /trips                        | { title, cityId }；创建 revision=1 的 draft     |
| GET    | /trips                        | page/pageSize，当前用户分页，默认 1/20，上限100 |
| GET    | /trips/:id                    | 读取当前用户的行程                              |
| PATCH  | /trips/:id                    | expectedRevision，title 和/或 planningInput     |
| PUT    | /trips/:id/selections         | expectedRevision、placeIds，保存景点选择顺序    |
| DELETE | /trips/:id?expectedRevision=N | 版本保护删除，204无响应体                       |

planningInput 支持 cityId、成对的 startDate/endDate、themes、pace、transportMode；不接受 selectedPlaceIds 或 days。空草稿可无日期、无景点；有日期时必须合法且包含首尾最多30天。中文主题与共享契约六类 Theme 枚举一一对应，保存读取不丢失主题。长城作为景点分类，兴趣归历史文化；旧浏览器缓存自动迁移。

读他人资源与不存在资源均返回404。未知字段/错误类型返回400。写操作在 PostgreSQL 事务中 SELECT FOR UPDATE 校验版本，并执行带 owner/id/revision 条件的更新；成功递增 revision，冲突返回409及 currentRevision。不在后台自动覆盖冲突。

已planned只改标题保留安排；改变规划条件或选择必须acknowledgeScheduleReset=true，否则409。确认后清空安排并转回draft。推荐确认、手动日程和版本保护删除均已实现；草稿保存本身不生成正式行程。

## 前端接口与调用顺序

新增 `features/trip-create/trip-draft-client.ts`：

- createTripDraftApi({ getAccessToken, baseUrl?, fetcher? })：create/get/list/update/setSelections。默认 /api，经已有 Vite 代理转发；token 来自 A 的登录模块，不在适配器硬编码或保存。
- toDraftPlanningInput：中文主题转枚举，空日期转 null。
- savePlanningDraft(api,draft,title,existingTrip?)：新建（如有需要）→更新规划输入→更新景点；每一步使用上一次返回的 revision。
- fromServerDraft(trip)：服务器草稿转为 NewTripPage 的 initialState；资源 ID 和 revision 由父级单独保留。只转换支持的北京草稿，拒绝 planned，避免丢失其每日安排。

多个 HTTP 请求不构成一个事务。`DraftSaveError.lastSavedTrip` 和 `.phase` 提供最后保存成功的资源、版本和失败步骤；父级必须保留该 ID，避免重试重复创建。冲突需要用户重新读取并处理，不自动重试覆盖。

NewTripPage 新增可选回调：

```ts
onSaveDraft?: (input: { title: string; draft: PlanningDraft }) => void | Promise<void>;
```

传入时显示“保存草稿”按钮；等待时防重复，失败保留输入。未接入时继续本地保存，页面不会声称服务器已保存。原 onBack/onComplete/initialState/initialView/storage 接口保持兼容。onComplete 仍是完整行程的未来提交入口，不能直接调用草稿接口伪造 planned。

A 的接入示意（以下变量由父页面提供）：

```tsx
const api = createTripDraftApi({ getAccessToken });
// remoteTripRef 保存服务端返回的完整 Trip，首次为 null。
async function handleSaveDraft({ title, draft }) {
  try {
    remoteTripRef.current = await savePlanningDraft(
      api,
      draft,
      title,
      remoteTripRef.current ?? undefined,
    );
  } catch (error) {
    if (error instanceof DraftSaveError && error.lastSavedTrip) {
      remoteTripRef.current = error.lastSavedTrip;
    }
    throw error;
  }
}
<NewTripPage onBack={returnToTripList} onSaveDraft={handleSaveDraft} />;
```

恢复：await api.get(id) → 父级保存 remoteTripRef → fromServerDraft 返回值传 initialState → 数据加载完成后挂载组件；切换资源时用 key 重新挂载。草稿缓存由父级按用户隔离。
