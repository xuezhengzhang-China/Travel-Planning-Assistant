# 服务器 Docker 数据库与本地开发

当前 B 环境采用“本地运行 Node.js，服务器 Docker 运行 PostgreSQL，通过 SSH 隧道连接”。服务器登录密码不保存在项目中；数据库使用独立随机密码，由被 Git 忽略的 .env 保存。

镜像通过腾讯云内网镜像源拉取，源地址保存在 .env 的 POSTGRES_IMAGE；数据库的公网入口不开放，使用 SSH 隧道连接。

## 2. 每次开发先开隧道

在第一个 PowerShell 终端运行：

```powershell
cd F:\TPA\Travel-Planning-Assistant\travel-planner-v2-framework
npm run db:tunnel:b
```

按 SSH 提示输入服务器密码，输入时不显示字符。成功后终端持续运行，没有业务输出是正常现象。保持这个终端打开；结束连接按 Ctrl+C。

本地 .env 的 DATABASE_URL 和 TEST_DATABASE_URL 已配置为隧道地址与对应数据库，并使用独立数据库密码。它们只保存在忽略文件中，不复制到说明文档或提交到 Git。

如果 55432 已被占用，先检查是否已有本项目的 SSH 隧道。只需要一条隧道；不要并行启动多个相同端口的隧道。

## 3. 在第二个终端运行测试或后端

完整测试顺序、手工请求示例和用例矩阵见 [B 完整测试流程与用例](B-完整测试流程与用例.md)。

```powershell
cd F:\TPA\Travel-Planning-Assistant\travel-planner-v2-framework
npm run test:integration:b
```

测试入口自动读取 .env 中的 TEST_DATABASE_URL，使用服务器上的专用测试库。预期报告 tests 8、pass 8、fail 0，其中包含 7 个真实 PostgreSQL 子场景。脚本在随机 schema 内运行迁移和测试，结束后清理自己的 schema。

快速测试仍直接在本地运行：

```powershell
npm test
```

启动本地后端：

```powershell
npm run dev:api
```

前端可在另一个终端运行 `npm run dev:web`。后端启动后，用另一个终端检查：

```powershell
Invoke-RestMethod http://localhost:3000/api/health
Invoke-RestMethod http://localhost:3000/api/ready
```

health 的 status 应为 ok；ready 的 status 应为 ready。若 ready 返回 503，检查 SSH 隧道和服务器容器状态。业务接口的真实认证仍待 C 接入，直接请求 B 业务接口返回 401 符合当前约定。

新迁移提交后，在隧道保持开启时执行：

```powershell
npm run db:migrate
npm run db:migrate:status
```

开发演示目录入口为 `npm run db:seed:b`，支持重复执行；它不创建用户账号。

## 4. 查看服务器状态

```powershell
ssh -p 22 ubuntu@120.53.94.209
```

登录后执行：

```bash
cd /home/ubuntu/tpa-b-db
sudo docker compose -f docker-compose.remote-db.yml ps
sudo docker compose -f docker-compose.remote-db.yml logs --tail 50 postgres
```

需要重新启动该项目时：

```bash
sudo docker compose -f docker-compose.remote-db.yml up -d --wait
```

数据库密码保存在该目录的 .env 中，权限为 600。数据位于专用 named volume，与 SSH 连接生命周期无关。普通关闭 SSH 隧道不会停止数据库。

## 5. 配置文件与复测证据

- docker-compose.remote-db.yml：专用数据库服务、loopback 端口、健康检查和持久化卷。
- scripts/remote-db/init-test.sql：首次初始化容器数据目录时创建独立测试库。
- scripts/remote-db/setup.py：服务器首次配置时生成私有 .env，启动专用 Compose 项目；保留已有 .env。
- package.json 中的 db:tunnel:b：SSH 本地端口转发入口，不调用本地 Docker 引擎。
