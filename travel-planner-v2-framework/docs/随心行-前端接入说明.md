# 随心行：与视频前端的接入说明

参考用户提供的4分37秒React前端演示：暖白纸色、鼠尾草绿、窄屏圆角卡片、分段进度、底部“旅行助手/行程/足迹/我的”导航。本次只调整行程模块与公共品牌，不重写首页、天气提醒、足迹或手账。

视频用于核对视觉和交互，不能提供对方真实路由、组件名称或状态结构。以下组件接口已在本项目实现，正式源码合并后仍需双方实际联调；不宣称已修改视频中的项目。

## 推荐接法：放入原来的“行程”页

公共入口为 apps/web/src/features/trip-create/index.ts，不必复制App.tsx或另外建立登录页面。

```tsx
import { useState } from 'react';
import type { Trip, PublicUser } from '@travel/shared';
import { TripWorkspace, type TripEntry } from './features/trip-create';

type Props = {
  user: PublicUser;
  getAccessToken: () => string | null | Promise<string | null>;
  onTripChanged: (trip: Trip) => void;
  onTripDeleted: (id: string) => void;
};
// 登录与列表缓存来自宿主；getAccessToken保持稳定引用。
function TripsPage({ user, getAccessToken, onTripChanged, onTripDeleted }: Props) {
  const [entry, setEntry] = useState<TripEntry>({ view: 'list' });

  return (
    <TripWorkspace
      key={user.id}
      embedded
      user={user}
      getAccessToken={getAccessToken}
      entry={entry}
      onNavigate={setEntry}
      onDraftSaved={onTripChanged}
      onSaved={onTripChanged}
      onDeleted={(trip) => onTripDeleted(trip.id)}
    />
  );
}
```

onTripChanged可把服务器Trip更新到宿主已有卡片缓存；模块自身列表始终读取服务器。视频中的外部“＋新建”或卡片按钮可通过setEntry打开对应入口。

| 对方页面上的操作 | 传给组件的entry                       |
| ---------------- | ------------------------------------- |
| 行程导航         | `{view:'list'}`                       |
| “＋新建”按钮     | `{view:'new'}`                        |
| 点开已有行程卡片 | `{view:'edit',tripId:服务器行程UUID}` |

entry变化会打开相应内容；内部操作通过onNavigate回传，父级需同步entry。切换登录用户时使用key重建。四步表单和服务器适配仍在模块内部完成，不要求前端同学重复编写。

## 宿主负责的部分

- 保留视频中原有品牌栏、四个底部导航与页面外壳。embedded会隐藏本模块重复品牌栏、账号栏和页脚，背景透明，不再创建另一组底部导航。
- 底部默认预留88px；宿主可在外层设置`--sx-host-bottom-space: 0px`，由自己的布局处理占位。
- 在独立页面项目中配置/api代理到后端。当前本机后端3001，其他人按.env配置，禁止把数据库连接和服务端Key放浏览器。
- 如果已有HTTP封装，可传api（TripDraftApi接口）。默认实现自动使用Bearer token；不接收ownerId作为身份。
- 保存通知返回完整服务器Trip，包含id/revision/status/planningInput/days，不能把它直接覆盖成视频本地自定义对象。需要旧卡片展示数据时显式转换；后续修改必须用服务器最新revision。
- onSaved/onDraftSaved/onDeleted是服务器操作成功后的通知，可用于更新缓存或重新查询。通知处理失败不会重复创建已保存行程；onNavigate处理页面切换。

## 名称、路由和样式

- 公共品牌为“随心行”，定义于branding.ts；浏览器标题、登录、列表、创建与编辑提示均统一。
- 独立联调App支持`/trips`、`/trips/new`、`/trips/:tripId/edit`，包括刷新直达和浏览器前进后退。可选tripEntryFromPath/tripEntryPath帮助对齐本项目路径；对方已有React路由时可直接将自己的路由转换为entry，不必照搬路径。
- `.suixin-trips`范围内的暖白、绿、边框和卡片风格参考视频，创建页使用四段细进度。没有复制视频插画、地图图片、宠物或业务内容。
- 手机适配按容器宽度计算，即使宿主在宽电脑视口中放置窄手机外壳，景点栏也会自动上下排列。
- 可通过CSS变量覆盖`--sx-accent`、`--sx-border`等颜色。没有修改全局style.css或后端数据结构。

## 数据边界

当前可保存目的地仍为北京，18个景点来自数据库。视频中的海淀区属于行政区展示，不能直接当城市UUID；天安门、鸟巢、水立方或任意自定义地点若未收录，也不能编造ID保存。需要扩展时先补核实资料与数据库记录，再接到选择页面。视频里的提醒、天气、足迹和手账仍由原负责人实现，不能把计划自动标成已到访。

## 验证结果

- 前端20项测试通过，包含入口路径、通知和原保存编辑流程；生产构建、类型和代码检查通过。
- 真实数据库测试宿主：打开新建→保存草稿回调→宿主按服务器UUID打开编辑→生成推荐→正式保存→回到宿主行程列表。测试宿主只用于本地验证，验证后移除，不作为对方真实项目。
- 1280px视口中的430px嵌入容器，日期及景点栏均按容器宽度排列；模块无横向溢出。补齐组件内部box-sizing，脱离原全局样式也可正常嵌入。
- 独立入口/trips/new刷新直达在React StrictMode下正常，不停在加载状态。
