## 1. 已交付内容

- 六个 HTTP 接口：城市、景点列表/详情、路线预览、逆地理编码、推荐生成。路径和字段以唯一的 [接口与数据约定 v1.1](接口与数据约定.md) 为准。
- BModule 注册入口、默认拒绝未认证请求的 Guard、可替换的 B_AUTHENTICATOR，以及 B 范围内的运行时校验和通用异常响应。
- PlacesService 供 C/D 使用的地点、有效城市和批量选择查询；GeoService 和 AmapClient 的地理解析、GPS 坐标转换能力。
- 纯计算规则排程、统一节奏参数、严格日历日期、时间/交通/休息预算、完整性检查、未安排项和来源警告。
- PostgreSQL 地点/方案仓库、两份增量迁移、幂等开发种子和 PROPOSAL_READER。生成推荐不写正式行程表。
- 高德 Web 服务适配：步行、驾车、公交、逆地理编码和 GPS 转换；区分 citycode 与 adcode，校验业务状态、耗时、超时和返回结构。
- 默认关闭的模型适配：使用可配置、兼容 Chat Completions 的服务，只允许原景点 ID 的完整排列；重新计算日程后才决定是否采用，失败保留规则结果。
- 前端原有 API 客户端内容保留，修复父级 lib/ 忽略规则导致该文件无法纳入版本控制的问题。

共享包新增 places.ts、recommendations.ts 及类型导出。没有引入第二套连接池、ORM 或测试框架，也没有新增项目运行时依赖。

## 4. 已验证的行为

快速测试覆盖：

- 日期包含首尾、同日、跨月跨年、有效闰日、无效日期及 30 天上限。
- 重复/空/未知/跨城景点、非法枚举、未知字段、坐标系与分页错误。
- 相同依赖下排程确定；景点恰好分布在已安排/未安排集合；空 day 保留；长景点不阻塞后续可安排项。
- 三种节奏的开始时间、数量、休息、预算刚好用尽和超预算；日程重复、遗漏、时间重叠等校验。
- 方案输入快照、有效期边界、返回对象修改不影响仓库、他人方案 404。
- B 的六个接口默认全部 401，伪造 Bearer token 或 x-user-id 不放行；测试认证后验证 200/400/500 响应及未知异常不回传 SQL/密钥。
- 地图业务失败、无效耗时、无路线、HTTP/JSON 错误、分钟转换、公交 citycode、区县映射和空城市。
- 无 Key 的短距离步行估算、其他场景失败；杭州两天三景点可通过改日安排获得合法方案。
- 模型禁用时不发请求；输出重复/伪造景点、拒绝、截断、非法 JSON、网络错误和真实本地 fetch 超时均回退。
- 模型候选必须重新排程且有改进才采用；候选路线失败保留原有效规则方案。

真实数据库的七个子场景：

1. 从只含初始 users/trips 迁移的库继续升级，三份迁移可重复检查，不重复执行已应用迁移。
2. 开发种子执行两次，仍为两个目的地、三个景点，且不偷偷创建用户。
3. 实际 SQL 验证筛选、主题排序、分页与总数、含引号的关键词、行政区映射和供应商城市码。
4. 经测试认证的 HTTP 请求真实生成并保存方案，trips 表仍为空。
5. 关闭并重新创建 Nest 应用和连接池后，仍可读取完整方案；他人读取 404，非法景点不写新方案。
6. 不替换地图/规则实现、不给地图 Key 的 HTTP 请求，真实使用估算与改日策略生成两天三景点并落库。
7. 实际外键拒绝不存在的城市，删除方案所有者后关联方案按约束清理。

## 5. 交接与运行

准备 Node、PostgreSQL 和 .env 后：

```powershell
npm ci
npm run db:migrate
npm run db:seed:b
npm run dev:api
```

种子命令只适用于开发，生产环境拒绝执行；创建的均为标记 fixture 的演示资料，不代表已核实的实时景点信息。正式业务接口在 C 接好认证前仍返回 401，这是当前明确的集成边界。

独立真实数据库测试：

```powershell
# 先创建专用测试库，将下面连接替换为自己的配置。
$env:TEST_DATABASE_URL = 'postgresql://你的用户:你的密码@localhost:5432/travel_planner_b_test'
npm run test:integration:b
```

- A 使用统一契约里的六个 B 接口、共享类型和警告码；需要展示未安排、估算和开放时间未核实状态。
- C 按统一契约第 6.4 节注册真实认证，并注入 PROPOSAL_READER；同一份方案仍需检查归属、有效期、输入快照、未安排项及 revision，正式行程写入由 C 负责。
- D 通过地点查询和 GeoService 获取城市；公共接口仍只接收 GCJ-02。GPS 转换导出为内部能力，设备定位的公共入口需另行约定。

模型启用条件、基础地址和回退策略见统一契约。结构化输出适配依据 [OpenAI 官方文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)；具体供应商、模型权限和输出格式兼容性仍需实际账号验证。高德字段适配依据 [路径规划 2.0 官方文档](https://developer.amap.com/api/webservice/guide/api/newroute)，未以模拟响应代替真实服务可用性证明。
