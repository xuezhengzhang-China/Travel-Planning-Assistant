# 按功能分支的日常操作

仓库：<https://github.com/zhangxuezheng-zxz/Travel-Planning-Assistant>。功能名称及路径见 [协作约定](分支结构与协作约定.md)。每个分支都保留完整工程。

## 1. 选择功能分支

先确认工作区状态，提交或妥善保留自己的未提交修改，再切换分支。示例以行程管理为例：

```powershell
Set-Location F:\TPA\Travel-Planning-Assistant
git status
git fetch origin
# 本地尚未建立该分支时
git switch --track origin/feature/trip-management
```

本地已有对应分支时：

```powershell
git switch feature/trip-management
git pull --ff-only
```

将名称替换成实际功能分支，不再按步骤或成员复制另一套长期分工。

## 2. 修改并推送对应模块

```powershell
git status
git add travel-planner-v2-framework/apps/api/src/trips
git add travel-planner-v2-framework/apps/api/tests/trips.test.cjs
git commit -m "feat(trips): 完善行程版本保护"
git push -u origin feature/trip-management
```

界面、后端和相应测试可在同一功能分支修改。共享入口、接口、迁移和 lockfile 的改动，需要说明调用方影响并协调相关模块。

向 `main` 发起 PR，描述功能、接口、验证结果和未完成项。不要用旧分支整个目录覆盖完整 `main`。

## 3. 合并后继续开发

功能分支长期保留。工作区干净时，将最新 `main` 正常合并回功能分支：

```powershell
git fetch origin
git switch feature/trip-management
git merge origin/main
# 若有冲突，按当前契约和双方有效修改处理并提交
git push
```

多人共享分支不强推、不重写已发布历史。原成员分支继续可查；迁移其新增工作前先比较差异，避免旧实现覆盖整合版本。

## 4. 测试与会议记录

```powershell
# 本地尚未存在时执行
git switch --track origin/test
```

全软件测试位于根目录 `APP_Test/`，依赖和测试库按其 README 配置。测试先于对应业务实现提交，0%/100% 以真实执行为依据；创建分支不表示测试已运行。

```powershell
git switch --track origin/meeting-records
# 在 docs/meetings/ 复制模板，填写真实会议内容
git add docs/meetings
git commit -m "docs(meetings): 记录会议决定与行动项"
git push
```

纪要写实际参会人、决定、受影响功能分支、负责人、截止日期和证据；尚未决定的内容保持待确认。

## 5. 查看新旧结构

```powershell
git branch -a
git log --graph --oneline --all
git show origin/integration-2 --stat
```

本轮保留全部旧分支，以正常合并把 `integration-2` 纳入 `main`，不删除分支、不强推、不重写历史。
